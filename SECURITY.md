# Security policy

## Supported code

Security fixes are accepted for the current OpenSageTV Vibe Linux server and
its active build/package workflow. Historical client, installer, and archived
third-party paths may be retained for compatibility but are not necessarily
commissioned or supported; see `TASKS.md` and `HANDOFF.md` for current status.

## Reporting a vulnerability

Do not publish credentials, private recordings, server configuration, or a
working exploit in a public issue. Use the repository's private vulnerability
reporting feature when it is available. If private reporting is unavailable,
open a public issue containing only a request for a private maintainer contact
and no vulnerability details.

Include the affected revision, platform, impact, and a minimal reproduction
that contains no private user data. Maintainers will acknowledge the report,
establish a private reproduction, and coordinate disclosure after a validated
fix is available.
